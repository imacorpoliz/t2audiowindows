## 1. Findings

### 1.1 Clock drift → periodic jumps in the sound (matters for Stage E and later)
* **Where:** `T2AudioStreamAdvanceLocked` (`src/WaveRTStream.c`). The source cursor runs on QPC, while the T2 reads the ring by its own crystal. The difference accumulates, and `T2AudioStreamFollowT2ClockLocked` corrects it with a `DestOffset` jump once the lead leaves 1000 ± 500 frames.
* **Evidence (simulation, `tests/T2AudioPipelineTest.c`):** at ±80 ppm, 5 jumps (`re-aimed`) and 5–9 discontinuities in 10 minutes: a jump in the signal or inserted silence, about once every 1–2 minutes. At 0 ppm the sound is continuous.
* **Why Stage D did not show it:** the runs lasted seconds.
* **What was done:** rate tracking `Parameters\ClockRateTracking`, **off by default** (§2.4).
* **What is needed from hardware:** the real T2 drift (`GEMINI.md` §7 E2/E3).

### 1.2 `Test-WasapiTone.ps1` wrote 16-bit samples into a 32-bit format
The non-float branch filled a `short[]` buffer for any integer format. The T2 endpoint is 32-bit PCM, so the tone would have been distorted and half the buffer length. Fixed: a separate branch for the 32-bit container.

### 1.3 `Test-WasapiTone.ps1` could play to the wrong device
If the endpoint was not found, the script silently played on the first active device and did not touch the volume or Mute. Dangerous for Stage E. Now `-EndpointVolume` mode requires an explicit `-DeviceId`, with no fallback. Endpoint volume ≤ 0.05, amplitude ≤ 0.1, Mute and volume 0 after the tone.

### 1.4 No level protection in the driver
Any volume or format bug would reach the speakers at full level. Added `OutputAttenuation`: −18 dB by default (§2.1).

### 1.5 Repository hygiene
* Binaries were in git: the signed `packaging/*.sys`/`.cat` (changed on every run) and `docs/research/*.exe`.
* Many outdated documents in `docs/`, `docs/planning/`, `SESSION_HANDOFF.md` (from 5 October). They contradicted the current state.
* Hard-coded paths `C:\Users\othysa\Desktop\mbp\...` in `tools/T2Audio-TestAgent.ps1`, `Capture-T2AudioLog.ps1`, `Test-MdlVariants.ps1`, `tools/README.md`.

### 1.6 CI did not check the C# in the scripts
The C# in `Test-WasapiRender.ps1`/`Test-WasapiTone.ps1` is compiled with `Add-Type` only when it runs on the test machine. A bug would have surfaced during a hardware run. Fixed (§2.3).

### 1.7 WDK code analysis (first run, CI run 40613510333)
Report-only mode. The driver code was **not** changed for these warnings: that would have made already-verified paths unverified. Assessment:

| Warning | Where | Assessment |
|---|---|---|

| C6101 `*ReplyBuffer` not set on the success path | `BceTransport.c:233` | When the reply is empty (`information == 0`) the buffer is untouched, and callers look at `ReplySize`. Safe, but the buffer could be zeroed. |

### 2.1 `Parameters\OutputAttenuation`
A right shift of every sample: 6 dB steps, default 3 (−18 dB), 0 turns it off, maximum 16. Applies to the stereo and raw paths. In the log: `mode parameters: … OutputAttenuation=3 (-18 dB)`. Tests: `tests/T2AudioSpeakerLogicTest.c`, section "Output attenuation". (Default changed to 1 after Stage E, §5.)

### 2.4 `Parameters\ClockRateTracking` (default 0)
* **At 0** the path is exactly the old one: `RatePpb` stays 0, and `T2AudioTicksToFramesPpb(…, 0)` equals `T2AudioTicksToFrames`, which a test checks.
* **At 1**, on every new T2 timestamp:
  * the source cursor is rebased (`AnchorFrames = playFrame`, `AnchorQpc = now`);
  * the rate is `RatePpb = drift + 1 ppm × (1000 − lead)`, clamped to ±1000 ppm;
  * drift is measured from the first timestamp of the run and clamped to ±500 ppm.
* The `re-aimed` jump remains an emergency path. The rate is reset on every RUN.
* Log: `T2 clock: rate=… ppb drift=… ppb lead=… (#n)`.
* Simulation: at ±80, ±300 ppm and with a wrapped hostTime, one jump at the start only, lead 960–1040.
* Known limitation: rounding during rebasing loses up to 1 frame per revolution. The lead settles about 40 frames from the target, well within ±500.

## 4. If something does not work
Do not fix the driver by guesswork. Order:
1. `.\tools\T2Audio-TestAgent.ps1 -Mode Recover`.
2. Keep `docs/logs/capture_agent_*` and the minidump.
3. Describe in `CURRENT_STATE.md` which step, what was expected and what happened.
4. Hand it to the owner, who will bring it to Claude.

Quick rollbacks without rebuilding (dword in `HKLM\SYSTEM\CurrentControlSet\Services\T2AudioMiniport\Parameters`, then restart the device):
* `ClockRateTracking=0`: the old clock;
* `OutputAttenuation=0`: no attenuation, as in 1.0.7.0 (only with the owner's permission);
* `TweeterMode=0`: tweeters silent (plain path);
* `SpeakerDsp=0`: no DSP.
