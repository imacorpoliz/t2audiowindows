## Analysis

### ✅ SUCCESSFUL STEPS
1. **DriverEntry**: `PcInitializeAdapterDriver` returned `STATUS_SUCCESS` (0x00000000)
2. **AddDevice**: `PcAddAdapterDevice` returned `STATUS_SUCCESS` (0x00000000): **STATUS_INVALID_PARAMETER (0xC000000D) FIXED**
3. **StartDevice entry**: the DeviceObject, Irp, ResourceList parameters are NOT NULL → "All parameters valid"

### ❌ BLOCKER
**T2AudioMapResources** returned `0xC0000182` (STATUS_DEVICE_CONFIGURATION_ERROR) at Device.c:82-107.

#### Possible failure points in Device.c:
```c
Line 35-36:  if (ResourceList == NULL) → 0xC0000182
             BUT the log shows "All parameters valid" → ResourceList != NULL

Line 38-41:  if (NumberOfEntriesOfType(CmResourceTypeMemory) < 2) → 0xC0000182
             ⚠ PROBABLE CAUSE: the PCI device was not given 2 memory BARs

Line 43-47:  if (FindTranslatedEntry(CmResourceTypeMemory, 0) == NULL) → 0xC0000182

Line 57-62:  if (FindTranslatedEntry(CmResourceTypeMemory, 1) == NULL) → 0xC0000182

Line 64-67:  if (Bar2Size <= T2AUDIO_GPR_OFFSET + 12) → 0xC0000182

Line 80-85:  if (version < 2 || signature != 0x19870423 || ...) → 0xC0000182

Line 89-95:  T2AudioFindSpeakerBuffer(...) returned an error
```

#### Why are there no resources?
- Registry: `HKLM:\...\4&3AC8FC3&0&03D8\LogConf` exists, but **BasicConfigVector is empty**
- Registry: `HKLM:\...\4&3AC8FC3&0&03D8\Resources` is **absent** (key not found)
- Win32_PnPAllocatedResource: **0 entries** for VEN_106B&DEV_1803
- SetupAPI: the diagnostic tool could not get the CM_RESOURCE_LIST (marshalling errors, APIs unavailable in user mode)

#### Hypothesis
**Apple T2 Audio (PCI\VEN_106B&DEV_1803) is a virtual device on the Intel PCIe bus (Parent: PCI\VEN_8086&DEV_A340) to which Windows does NOT assign MMIO resources automatically.** (Later disproved: the resources exist; the failure was in the driver's own checks, see `docs/archive/MAPRESOURCES_ROOT_CAUSE.md`.)

On macOS the T2 Audio resources are assigned through a special mechanism (AppleAVD/AppleAVE/iBridge). On Windows the INF has no `LogConfig` or `PnpLockdown` directives that would request specific BAR addresses from the PCI bus driver.

**Result:** PortCls calls `T2AudioStartDevice(ResourceList=<valid pointer>)`, but `ResourceList->NumberOfEntriesOfType(CmResourceTypeMemory)` returns **0** or **1** (fewer than the required 2).

## Conclusion

### ✅ Achieved
- **STATUS_INVALID_PARAMETER (0xC000000D) FIXED**: the PcAddAdapterDevice arguments are now right (MaxObjects=16, DeviceExtensionSize=632).
- **DriverEntry, AddDevice, StartDevice entry — SUCCESS**.
- KdPrint logging works (28 strings in the binary, 8 captured with DebugView).

### ❌ Blocker
**T2AudioMapResources failed: 0xC0000182**: the device was not given PCI memory resources (BAR0/BAR1).

### Next step
1. Add a KdPrint before every `return STATUS_DEVICE_CONFIGURATION_ERROR` in Device.c to pinpoint the failure (line 39, 46, 60, 65 or 83).
2. If `NumberOfEntriesOfType(CmResourceTypeMemory) < 2` is confirmed:
   - Study how AppleAudio.sys gets around it (it may use IoGetDeviceProperty/CM_Get_DevNode_Registry_Property instead of the ResourceList).
   - Or add a `LogConfig` directive to the INF with fixed BAR addresses from the parent device in Device Manager (if known).
   - Or rewrite T2AudioMapResources to work with an empty resource list, getting the BARs through other APIs (e.g. `HalGetBusDataByOffset` or reading the PCI config space directly).
