## Analysis

### ✅ УСПЕШНЫЕ ЭТАПЫ
1. **DriverEntry**: `PcInitializeAdapterDriver` вернул `STATUS_SUCCESS` (0x00000000)
2. **AddDevice**: `PcAddAdapterDevice` вернул `STATUS_SUCCESS` (0x00000000) — **STATUS_INVALID_PARAMETER (0xC000000D) ИСПРАВЛЕН**
3. **StartDevice entry**: параметры DeviceObject, Irp, ResourceList НЕ NULL → "All parameters valid"

### ❌ БЛОКЕР
**T2AudioMapResources** вернул `0xC0000182` (STATUS_DEVICE_CONFIGURATION_ERROR) на строке Device.c:82-107.

#### Возможные точки отказа в Device.c:
```c
Line 35-36:  if (ResourceList == NULL) → 0xC0000182
             НО лог показывает "All parameters valid" → ResourceList != NULL

Line 38-41:  if (NumberOfEntriesOfType(CmResourceTypeMemory) < 2) → 0xC0000182
             ⚠ ВЕРОЯТНАЯ ПРИЧИНА: PCI-устройству не выделено 2 memory BAR

Line 43-47:  if (FindTranslatedEntry(CmResourceTypeMemory, 0) == NULL) → 0xC0000182

Line 57-62:  if (FindTranslatedEntry(CmResourceTypeMemory, 1) == NULL) → 0xC0000182

Line 64-67:  if (Bar2Size <= T2AUDIO_GPR_OFFSET + 12) → 0xC0000182

Line 80-85:  if (version < 2 || signature != 0x19870423 || ...) → 0xC0000182

Line 89-95:  T2AudioFindSpeakerBuffer(...) вернул ошибку
```

#### Почему нет ресурсов?
- Реестр: `HKLM:\...\4&3AC8FC3&0&03D8\LogConf` существует, но **BasicConfigVector пуст**
- Реестр: `HKLM:\...\4&3AC8FC3&0&03D8\Resources` — **отсутствует** (ключ не найден)
- Win32_PnPAllocatedResource: **0 записей** для VEN_106B&DEV_1803
- SetupAPI: диагностический инструмент не смог получить CM_RESOURCE_LIST (ошибки marshalling, API недоступны в user-mode)

#### Гипотеза
**Apple T2 Audio (PCI\VEN_106B&DEV_1803) — это виртуальное устройство на шине Intel PCIe (Parent: PCI\VEN_8086&DEV_A340), которому Windows НЕ назначает MMIO-ресурсы автоматически.**

В macOS ресурсы для T2 Audio выделяются через специальный механизм (AppleAVD/AppleAVE/iBridge). В Windows INF не содержит директив `LogConfig` или `PnpLockdown`, которые бы запрашивали конкретные BAR-адреса у PCI Bus Driver.

**Результат:** PortCls вызывает `T2AudioStartDevice(ResourceList=<valid pointer>)`, но `ResourceList->NumberOfEntriesOfType(CmResourceTypeMemory)` возвращает **0** или **1** (меньше требуемых 2).

## Conclusion

### ✅ Достигнуто
- **STATUS_INVALID_PARAMETER (0xC000000D) ИСПРАВЛЕН**: аргументы PcAddAdapterDevice теперь правильные (MaxObjects=16, DeviceExtensionSize=632).
- **DriverEntry, AddDevice, StartDevice entry — SUCCESS**.
- Логирование через KdPrint работает (28 строк в бинарнике, захвачено 8 через DebugView).

### ❌ Блокер
**T2AudioMapResources failed: 0xC0000182** — устройству не выделены PCI memory resources (BAR0/BAR1).

### Следующий шаг
1. Добавить KdPrint перед каждым `return STATUS_DEVICE_CONFIGURATION_ERROR` в Device.c, чтобы точно определить точку отказа (line 39, 46, 60, 65, или 83).
2. Если подтвердится `NumberOfEntriesOfType(CmResourceTypeMemory) < 2`:
   - Исследовать, как AppleAudio.sys обходит проблему (может использовать IoGetDeviceProperty/CM_Get_DevNode_Registry_Property вместо ResourceList).
   - Либо добавить в INF директиву `LogConfig` с фиксированными BAR-адресами из Device Manager родительского устройства (если известны).
   - Либо переписать T2AudioMapResources для работы с нулевым списком ресурсов, получая BAR через альтернативные API (например, `HalGetBusDataByOffset` или прямое чтение PCI config space).
