## kaiT2en (Linux iBridge/T2 Audio Driver)

**Source:** https://github.com/kaiT2en/KaiT2en-Fedora (`modules/t2bce_audio`), earlier https://github.com/kekrby/linux-t2  
**License:** GPL-2.0  
**Used in:** `src/BceTransport.c`, `src/BceProtocolLogic.h`, `src/WaveRTStream.c`, `src/Device.c`

This project references protocol constants and structures from the Linux kaiT2en driver for Apple T2 audio devices. Specifically:

- BCE (Bridge Co-processor Engine) protocol constants
- Message type definitions (TAG, command/response types)
- Device communication patterns
- Property selectors (`'pft '`, `'ltnc'`, `'saft'`), the stream physical-format
  descriptor layout and its mapping to a sample layout (S24_LE for the speaker)
- Init / quiesce ordering (ring cleared and clock anchored before `START_IO`,
  `SET_REMOTE_ACCESS(OFF)` on teardown, write-combining for a prefetchable BAR)

**Attribution comment in source:**
```c
// T2 BCE Protocol constants (from Linux KAIT2EN)
```

The Windows implementation in this project is original work but relies on protocol knowledge derived from reverse engineering documented in the Linux driver.

**Timestamp handling (2026-10):** dropping timestamps older than the run's
`START_IO` and the plausibility check on `hostTime` follow kaiT2en commits
`bbf3878` / `6128f86` (`modules/t2bce_audio/pcm.c`).

**DSP profile (separate license):** the speaker channel layout used in
`src/T2AudioSpeakerLogic.h` (ring channels 0/1 and 3/4 = woofers, 2/5 =
tweeters) was read from `dsp/profiles/16_1/graph.json`, Copyright (C) 2026
André Eikmeyer, KAIT2EN, GPL-3.0-or-later with the attribution term of its
`LICENSING.md`. The tweeter high-pass of the plain path is an independently
computed Butterworth filter.

## Note on what is original and what is derived

The driver code (WDM / PortCls, the BCE transport, the WaveRT streams, the
fixed-point DSP engine, the microphone capture) is original and contains no
copied source code. Protocol constants and structure layouts come from the
KAIT2EN / linux-t2 research and from our own reverse engineering of Apple's
Windows drivers (below). **However, the DSP coefficient tables
(`src/T2AudioDspProfile16_1.h`) and the microphone chain constants
(`src/T2AudioMicLogic.h`) are derived from KAIT2EN's GPL-3.0-or-later DSP
profile**, so a built driver must be distributed under GPL-3.0-or-later
(see the KAIT2EN section above). An earlier version of this note said the
driver contained no GPL-derived material; that stopped being true when the
DSP was added (2026-10-28).

## KAIT2EN microphone profile

`src/T2AudioMicLogic.h` implements `dsp/profiles/16_1/mic.json` of KAIT2EN
(beam = 0.5·mic0 + 0.5·mic1, the 48 kHz high-pass biquad, the +39 dB output
gain), Copyright (C) 2026 André Eikmeyer, GPL-3.0-or-later with the
attribution term of KAIT2EN `LICENSING.md`.

## lsp-plugins (reference only)

The `CompStyle=1` compressor detector (RMS over 10 ms, ±6 dB soft knee) and
the K-weighted autogain follow the documented behaviour and defaults of
lsp-plugins `mb_compressor` and `autogain` (LGPL-3.0) as configured in the
KAIT2EN graph. No lsp-plugins code was used; the K-weighting coefficients are
the public ITU-R BS.1770 values.

## Reverse engineering of Apple's Windows drivers

How AppleUSBVHCI delivers T2 messages (IOCTL 0x222020), the microphone
registration message (837-byte `SET_INPUT_STREAM_ADDRESS_RANGES`), the
`'nsrt'` sample-rate property, the BufferStruct entry AppleAudio appends for
the microphone, and the power handling were learned by static analysis of
`AppleAudio.sys` and `AppleUSBVHCI.sys` (Ghidra) for interoperability, and
are documented in `docs/analysis/`. No Apple code is included.

## bankstown (virtual bass)

**Source:** https://github.com/chadmed/bankstown (`bankstown-lv2`), via the
C++ port in `imacorpoliz/mbp` `SpeakerDSP-APO/vst/src/bankstown_vst2.cpp`
**License:** MIT, Copyright (C) 2023 James Calligeros <jcalligeros99@gmail.com>
**Used in:** `src/T2AudioDsp.h` (`T2DspVirtBass`, `T2DspTanh`), filter and gain
constants in the generated `src/T2AudioDspProfile16_1.h`

The algorithm (band-pass 40-150 Hz, asymmetric tanh saturation, band-limit
to 200-450 Hz, add to the dry signal) is re-implemented in fixed point; the
settings come from the KAIT2EN 16_1 graph. The MIT license requires keeping
the copyright notice above and the MIT permission notice (full text in the
upstream repository's `LICENSE`) with copies of the software.
